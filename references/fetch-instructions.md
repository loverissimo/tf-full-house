# Module Fetch Instructions – Deloitte Terraform Full House

Part of: deloitte-terraform-full-house  
Purpose: Define the required process for retrieving Terraform modules from the Deloitte Azure repository and integrating them into a generated Terraform project.

This document defines the **mandatory process** the agent must follow to obtain Terraform modules. Modules must **always be fetched from the repository** and must **never be generated manually**.

---

# Module Source Repository

All Terraform modules are stored in the Deloitte Azure DevOps repository:

Terraform Repository for Azure  
https://github.com/loverissimo/terraform-repository/tree/master/azure

Modules are organized using the following structure:

/azure/<theme>/<module_name>/

Example:

/azure/networking/vnet/
/azure/compute/vm/
/azure/management/resource_group/

Each module folder must contain:

main.tf
variables.tf
outputs.tf
status.md (optional)

---

# Mandatory Module Fetch Rule

Terraform modules **must never be generated by the agent**.

The agent must **always retrieve modules from the repository** using the fetch script.

If a requested module does not exist in the repository:

- Do **not** generate Terraform resources
- Do **not** create a new module
- Inform the user that the module does not exist

---

# Script Execution

The agent must execute the fetch script using a resolved explicit path. Do not assume the target repository contains `scripts/fetch-modules.sh`.

Resolution order:
1. `./scripts/fetch-modules.sh` (if running inside a repo that includes the script)
2. `~/.github/skills/full-house/scripts/fetch-modules.sh`
3. `~/.github/skill/full-house/scripts/fetch-modules.sh`

Then execute:

bash <resolved_script_path> <module_name> resources/<module_name>

Where:
- <module_name> is the module requested by the user (e.g., vnet, resource_group, vm)
- resources/<module_name> is the destination directory in the Terraform project

Example:
bash "$SCRIPT_PATH" resource_group resources/resource_group
bash "$SCRIPT_PATH" vnet resources/vnet

# Fetch Process

When infrastructure is requested, the agent must perform the following steps:

1. Identify the Terraform module required.

2. Resolve `SCRIPT_PATH` and execute:

bash "$SCRIPT_PATH" <module_name> resources/<module_name>

3. The fetch script searches all theme folders under:

/azure/

until it finds a folder matching <module_name>.

If the module folder is not found in the repository,
the script must stop and the agent must inform the user
that the requested module does not exist.

4. Once found, the script copies the module files:

main.tf
variables.tf
outputs.tf
status.md (if present)

5. The module is placed in the project under:

resources/<module_name>/

# Module Placement Rules
Modules must always remain inside the resources/ directory.

Example project layout:

.
├── main.tf
├── variables.tf
├── terraform.tfvars
├── provider.tf
├── locals.tf
└── resources/
     ├── resource_group/
     │    ├── main.tf
     │    ├── variables.tf
     │    ├── outputs.tf
     │    └── status.md
     └── vnet/
          ├── main.tf
          ├── variables.tf
          ├── outputs.tf
          └── status.md

The root project must never contain resource blocks copied from modules.
Root Terraform files must only contain module calls.
